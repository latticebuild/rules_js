# Runnable examples

Prepare the repository with `mise run bootstrap`, then run:

```sh
bazel build //examples/svelte:artifacts
bazel test //examples/svelte:test
```

| Feature | Source | Command | Expected result |
| --- | --- | --- | --- |
| SvelteKit sync, route declarations and TS inheritance | [kit/BUILD.bazel](kit/BUILD.bazel) | `bazel build //examples/svelte/kit:typecheck` | A typed PageLoad consumes generated route $types. |
| Editor refresh and explicit writer | [kit/BUILD.bazel](kit/BUILD.bazel) | `bazel run //examples/svelte/kit:kit_write` | Writes generated ignored configuration/types to this checkout; building does not write source. |
| Config, staged-input and secrets refusals | [../tests/svelte/BUILD.bazel](../../tests/svelte/BUILD.bazel) | `bazel test //tests/svelte:kit_test` | Owned analysis and writer cases retain boundary coverage. |

The root artifact/test gates include these examples. Deliberately invalid subjects
remain in test fixtures; their owner tests require the expected refusals. Fix and
editor-write commands modify the invoking checkout only when run explicitly.
Automated mutation cases use disposable invoking workspaces.

The same BUILD file declares `write_config` with the standalone
`js_svelte_kit_write` API. `kit_write` is generated by `js_svelte_kit`; both write
the invoking checkout only when explicitly run. Both executables are built by
the example artifact gate.
